An agentic marine-intelligence platform for Indian fishermen, coastal authorities and disaster agencies. Natural-language question in any of nine coastal languages; satellite Earth observation, ocean model output and meteorological advisories fused underneath; an explainable, evidence-cited recommendation out — with the safety verdict itself produced by a deterministic rule engine, never by a model.

End-to-end system architecture

Read it top to bottom. A question enters at Tier 0 in whatever language and channel the user has, is normalised at Tier 2, planned and decomposed at Tier 3, and answered from pre-computed data at Tiers 4 and 5. The single structural decision worth defending is the line drawn between Tier 3 and Tier 4: everything above it is probabilistic and helpful, everything below it is deterministic, versioned and auditable.

The two vertical rails carry the request down the left and the answer back up the right, labelled with what actually crosses each boundary. The red rail on the far right is the one that makes this agentic rather than conversational — a rules-triggered alert that reaches the boat without anyone having asked a question.

While this is on screen

  1. Tier 0 to Tier 2. “A fisherman asks in Tamil, by voice, from a phone on 2G. We detect the language, transcribe it, and translate to a canonical English query — nine coastal languages, three independent stacks behind one interface.”
  2. Tier 3. “The planner emits an explicit plan before it executes anything. You can see which specialists it chose and why. That is the difference between an agent and a chatbot.”
  3. The line. “Nothing below this line contains a model. The go/no-go verdict is a pure function of forecast variables and this boat’s class, from a versioned threshold table. The model is allowed to explain that verdict and to translate it. It is not allowed to issue one.”
  4. Tier 5 to Tier 6. “We do not call a third-party API inside the request. We ingest on a schedule, derive the fields we need, and every value we quote carries its dataset id, its valid time and its age.”
  5. The red rail. “And this is the part nobody asked for. The system watches the filed trip plan and interrupts — wind rising, return by 13:00 — over WhatsApp, SMS, or NavIC when the boat is past cellular coverage.”
The question you will be asked“Would you trust an AI to tell someone it is safe to sail?” The honest answer is on the diagram: we do not. A rule engine issues the verdict, a second agent adversarially checks the explanation against it, and low confidence escalates to a human channel instead of guessing harder. ORCA supplements official IMD and INCOIS bulletins; it never replaces them.

Plate 01detail

Ingest & Earth-observation processing

Everything the agents can answer with is produced here, on a schedule, before anyone asks a question. The request path never calls a third-party API directly — a live call happens only when the cache misses and the source is reachable, and the answer then carries a staleness note.

  • Cadence1 h waves and wind · 6 h SST and chlorophyll · 15 min alerts and AIS
  • Area of interest60–100°E, 0–25°N — the Indian EEZ envelope
  • Toolchaincopernicusmarine · earthaccess · xarray + dask · rio-cogeo · pgstac
  • Versioningthe STAC Item datetime is the version tag — “show me the SST layer as it was three hours ago” is a catalogue query

Plate 02detail

Deriving the Potential Fishing Zone

INCOIS publishes PFZ advisories as PDF maps and regional-language text, not as an API. Scraping the WebGIS is fragile. The published methodology, though, is public — so ORCA reimplements it and validates against the official bulletins rather than depending on them.

  • Thermal frontsCayula-Cornillon SIED (1992); a Sobel 90th-percentile gradient mask stands in for the MVP
  • Chlorophyll frontsCanny edge detector, σ = 2.0, on the ocean-colour raster
  • Productivity cutChl-a > 0.3 mg m⁻³
  • Honesty on stagesay which of the two front detectors is actually running — judges reward the distinction and punish blurring it

Plate 03detail

Language and voice round trip

This is a scored line in the problem statement and it is testable in five seconds, so it is built with three independent stacks behind one interface. The unglamorous part — verifying that numbers survived translation — is the part that matters in a safety system.

  • DetectIndicLID handles native script and romanised typing; fastText lid.176 as fallback
  • Coverageall nine coastal-state languages across ASR, translation and TTS — except Konkani TTS
  • Why translatekeeps the English RAG corpus usable and puts the strongest reasoning model where it is strongest; the cost is 1–3 s and translation drift
  • Fallback orderself-hosted AI4Bharat → Sarvam API → Bhashini/ULCA — never a single dependency

Plate 04detail

Agent graph topology

The problem statement asks for autonomous planning and tool selection. A hardcoded chain is not that. This is a supervisor graph: the planner emits an explicit plan, delegates to specialists, and a critic can bounce the draft back before anything is released.

  • FrameworkLangGraph + langgraph-supervisor; Google ADK + A2A as the fallback story
  • PersistencePostgresSaver keyed by thread_id — interrupt, resume, time travel
  • Streamingastream_events gives node events and tokens, which is the trace UI for free
  • Observabilityevery run and step written to agent_runs / agent_steps, mirrored to Langfuse

Plate 05detail

One query, end to end

The trace of a single spoken Tamil question from a boat registered at Kasimedu — 8.2 m LOA, 2.6 m beam — through every lane of the system. Note step 8: the critic rejects the first draft for being too soft against a 25/100 index.

  • The question“நாளை காலை கடலுக்குப் போவது பாதுகாப்பானதா?” — is it safe to go to sea tomorrow morning?
  • The verdictindex 25/100, two hard vetoes → NO-GO, issued by the rule engine, not the model
  • What the user hearsthe verdict, the two vetoes in plain Tamil, and what would have to change for it to be a yes
  • What is loggedthe plan, every tool call and result, the critic's rejection, and the thresholds version used

Plate 06detail

The deterministic safety core

A jury member is silently asking whether they would let an AI tell a man it is safe to take a wooden boat out. This diagram is the answer. The verdict is a pure function of forecast variables and boat class; the model is allowed to phrase it and nothing else.

  • Verdict ownera pure function over a versioned boat_classes table — no model in the path
  • Hard vetoesany single limit breach overrides the blended index outright, and the breach is quoted to the user
  • Escalationconfidence low or data stale → “confirm with your fisheries office / VHF ch. 16”
  • Provenanceevery output carries thresholds_version and the citation for each number

Plate 07detail

Geofencing and the proactive alert

The Potential Fishing Zone advisory says where the fish are. It does not say whether reaching them crosses into Sri Lankan or Pakistani waters. That gap is the one with a human cost attached, and closing it is mostly two spatial queries and a projection.

  • Coarse filterRedis GEOSEARCH over fence centroids — circles and boxes only, which is why the second pass exists
  • Exact passST_Contains and ST_Distance(geom::geography, …) — the cast is what makes the answer metres
  • Fence sourcesMarine Regions EEZ v12 · WDPA marine protected areas · state trawl-ban zones · CRZ-IV
  • DeliveryCAP 1.2 record, then FCM / WhatsApp / SMS, and NavIC beyond cellular coverage

Plate 08detail

Safe-route optimisation

searoute-py gives you a land-avoiding shortest path in one call, and you should use it as the baseline. What it cannot do is tell the skipper why the direct line was rejected — and that sentence is the actual deliverable.

  • Graphdirected — current assist is asymmetric by direction of travel
  • Blocked edgesland · Hs > 1.5 × class limit · any exclusion polygon, each with a stated reason
  • Searchnetworkx.astar_path with a Haversine heuristic; scikit-image.graph on a cost raster is the faster build
  • Explainabilityper-leg km, wave height and current assist written to agent_steps.output for the reporting agent to quote

Plate 09detail

Frontend render pipeline

The chat does not describe the map — it drives it. The visualisation agent emits a ui_spec and the layer registry turns it into concrete GPU layers, so the causal link between what the agent said and what the map did is visible on screen.

  • PrimaryMapLibre GL v5 globe projection + deck.gl via MapboxOverlay — free, no token, no quota on demo day
  • CinematicCesium + Resium for a single opening flythrough; ion's free tier will not survive repeated refreshes
  • Particlesweatherlayers-gl ParticleLayer over a u/v PNG (R = u, G = v) with a JSON sidecar
  • Insurancebasemap pre-baked as a single PMTiles archive on static storage — nothing fetched live during the demo

Plate 10detail

Deployment and demo-day topology

Free tiers are not free of behaviour. Three of them sleep, pause or wipe state on a schedule that lines up uncannily well with a judging slot, so the topology is chosen around which ones stay awake.

  • ComputeGoogle Cloud Run — the always-free tier here is permanent, not a trial
  • DatabaseNeon Postgres with PostGIS and pgvector; autosuspend after 5 min idle cannot be disabled
  • Cache and queueUpstash Redis, which persists — Render's free tier is in-memory and silently drops the ARQ queue
  • StorageCloudflare R2 — tile reads are egress-heavy and R2 charges nothing for egress
